记录 FileButler 开发中**为什么这样做**、**哪里栽过跟头**、**现在能做到哪一步**。结果数字和完整实验过程见

## 一、技术取舍

### 1. 架构与模型

| 决策 | 选择 | 备选 | 为什么 | 代价 |
|---|---|---|---|---|
| Agent 框架 | 手写循环（`agent/loop.py`） | LangChain / LangGraph | 每一步可见、可插桩：自检、上下文压缩、成本统计都是在循环里插几行实现的；面试能讲清楚每一步 | 重试、Token 统计、消息格式转换都要自己写 |
| 调用方式 | 原生 Function Calling | ReAct 文本解析 | 结构化输出，不用写正则解析，参数错误能由 pydantic 精确报出 | 依赖模型的工具调用能力；ReAct 对比（E3）还没做 |
| 模型 | `deepseek-flash`，经 `openai` SDK | 本地模型、其他厂商 | 便宜、有前缀缓存、OpenAI 兼容，换模型只改配置 | 结论绑定 DeepSeek 的定价结构（尤其是缓存价只有 1/50） |
| 工具参数 | pydantic 模型，自动生成 JSON Schema | 手写 Schema | 代码和描述不会不一致；校验错误能精确到字段，回传给模型自我纠正 | Schema 里会带 `title` 等冗余字段，占 Token |
| 工具返回 | 纯文本，统一 `OK:` / `ERROR:` 开头 | 结构化 JSON | 模型读起来最自然；除网络错误外，所有错误都回传给模型而不是让程序崩溃 | 程序要从文本里解析结果（自检、压缩都依赖这个约定） |
| 系统提示词 | 只放静态内容 | 放日期、run_id 等动态信息 | 实测：开头多一行日期，缓存命中从 88% 掉到 0%。系统提示词加工具定义约 1900 Token，必须逐字不变 | 需要动态信息时只能放在用户消息里 |

### 2. 安全

| 决策 | 选择 | 备选 | 为什么 | 代价 |
|---|---|---|---|---|
| 删除 | 不提供删除，只有 `trash`（移入 `.trash/`） | 提供 delete 加确认 | 最可靠的安全措施是没有这个能力；所有操作都可逆，“文件一个不少”才能作为不变量检查 | 回收区只增不减，需要用户自己清理 |
| 路径校验 | 拼接沙盒根目录 → `resolve()` → `is_relative_to` | 字符串前缀检查 | `resolve()` 会展开 `..` 和符号链接；字符串检查挡不住 `a/../../etc` | 指向沙盒外的符号链接一律拒绝，哪怕用户本意是想访问 |
| 名字容错 | 模型给的路径：统一 NFC、匹配首尾空格、换成磁盘上的真实名字；undo 用 `exact` 模式原样使用 | 严格按字符串匹配 | 真实文件名里有空格开头、连字 `ﬀ`、NFD 写法，严格匹配会找不到文件或悄悄改名（见坑 12、13） | 容错和精确两套规则，`sandbox.path()` 变复杂了 |
| undo 冲突 | 原位置被占用就跳过并报告，不覆盖 | 强行覆盖 | 用户可能在运行之后自己动过文件，覆盖会造成二次损失 | 不保证一定能完全还原，需要看报告 |
| 确认机制 | `risky`：只在 trash 或一次运行动过 10 个以上文件时问；只接受 `y` / `n` / `a`，其他输入要求重输 | 每步都问；识别自然语言 | 每步都问会让人麻木；猜自然语言的意思不可靠（见坑 2） | 10 个文件以内的批量移动不会被问到 |
| 注入防护 | 文件内容包在 `<file_content>` 里，系统提示词说明“标签内是数据” | 过滤可疑文本 | 过滤规则永远不全；隔离加上确认和 undo 兜底，层层设防 | 最终靠模型遵守；测试覆盖有限（见第三部分） |

### 3. 评测

| 决策 | 选择 | 备选 | 为什么 | 代价 |
|---|---|---|---|---|
| 判定方式 | 检查沙盒最终状态（断言）加不变量 | 让大模型当裁判 | 确定、可复现、零成本；“文件 MD5 多重集合不变”能直接抓到程序 bug | 只能判结果，判断不了过程是否合理（比如多余的操作） |
| 主评测数据 | **真实数据**（51 篇论文）；合成数据只做自检和回归 | 只用合成数据 | 合成数据加难度后仍有 95%，区分度不够；真实数据测出了 4 个合成数据永远测不出的工具 bug | 真实数据不能进 git，换台机器就复现不了；标注要花人力 |
| 真实数据标注 | 由 Claude 标注（不是被测的 DeepSeek），每条写明依据 | 让被测模型标；纯人工标注 | 被测模型来标等于自己考自己；标题等客观字段用脚本预填，主观的主题由另一个模型查原文判断 | 只有一个标注者，没有一致性检验 |
| 分类标准 | 按论文**用的方法**分（BERT 算 transformer，用 CNN 加注意力的 MVNN 不算） | 按研究对象分 | 标准统一，可以查原文验证 | 和用户原来的归类不完全一致（MVNN 原本在 transformer 文件夹里） |
| 宽松断言 | `placed`（落在任一可接受分类即可）、`retitled`（新名字包含标题关键片段）、`except` | 精确路径匹配 | 真实论文常常跨主题；真实标题里有冒号这类不能用在文件名里的字符 | 断言变宽松，判对的门槛降低了 |
| 合成数据 | 固定种子，逐字节可复现（PDF 创建时间、zip 时间戳都固定） | 每次随机生成 | 实验之间才能比较 | 生成器里处处要小心随机数的消耗顺序（见坑 7） |
| checker 自检 | 标准答案 Agent 必须全过、什么都不做的 Agent 必须全挂 | 只信 checker | checker 写错了，所有实验结论都会跟着错；这套自检抓到过 checker 的 bug（坑 4） | 自检代码几乎和 checker 一样长 |
| 复现失败 | `eval/replay.py` 从任意一步截断重跑；低频失败录成确定性回归测试 | 只靠重跑 | 1/70 的随机错误重跑 70 次未必能遇到一次 | 录下来的用例只能验证程序的应对，不能代表模型的行为 |
| 重复次数 | 每个任务 5 次 | 3 次 | 1–2% 的失败率，3 次基本测不出 | 成本高一些；5 次仍然分不清 1 次以内的差异 |

### 4. 成本与上下文

| 决策 | 选择 | 备选 | 为什么（数据） | 代价 |
|---|---|---|---|---|
| 成本统计 | 缓存命中、未命中、输出三部分分别计价 | 只看总 Token | 七八成 Token 命中缓存，命中价是未命中的 1/50（flash 高峰时段 0.04 对 2 元/百万）；按总 Token 估算会把成本高估好几倍 | 价格要写进配置，并跟着官网更新 |
| 预算口径 | **按费用**：每次运行 ¥0.30 | 按 Token：5 万 | 按 Token 计时，300 个文件的任务 B10 是 0/5；改按费用后 5/5，每次实际只花 ¥0.22 | 没配价格的模型要退回按 Token 计 |
| 结束前自检 | 动过 ≥5 个文件才触发，追加在对话末尾，最多一次；**默认关闭** | 每次都自检；每步都反思 | 在已经漏移文件的位置回放：关闭时 10/10 失败，开启时 10/10 补上。加上 ≥5 的阈值后，触发次数减少 47%，每次运行成本只增加 12% | 对 1–4 个文件的小任务不起作用；全量评测里看不出收益（任务太简单） |
| 上下文压缩 | 已实现（高水位一次压一批、规则摘要），**默认关闭** | 默认开启 | E6 实验：R06 上 Token 减半，费用反而增加 25%。压缩会改写旧消息，缓存失效，命中率 87% 跌到 45%；规则摘要还导致平均重读 6.4 次 | 上下文超出模型窗口时才需要它，目前还没遇到这种任务 |
| 列表输出 | 按字数分页，只在整行之间切分 | 按条数分页 | 51 个长文件名超过单条结果 2000 字的上限，被拦腰截断（见坑 10） | 每页条数不固定 |
| PDF 解析 | PyMuPDF，出错时退回 pypdf | 只用 pypdf | 51 篇真实论文：pypdf 1 篇乱码，PyMuPDF 0 篇，速度快 3 倍 | **AGPL-3.0 许可**：闭源商用要换库或购买授权 |
| 内容检索（2026-10-18 实现） | 标准库实现 BM25，作为 Agent 可选只读工具；前两页按论文评分 | 向量检索、SQLite FTS、外部 BM25 库 | 先对 51 篇真实论文建立可解释基线，无 embedding/数据库依赖；聚焦按主题找候选 | 不自动翻译、不扩同义词；正文后面的内容不可检索，top-k 不保证找全；此诊断集上未优于词项覆盖数基线 |

## 二、踩过的坑

按“现象 → 原因 → 修复 → 教训”记录。**加粗**的是只有真实数据或真实终端才会暴露的问题。

### 交互与输出

1. **确认提示里看不到选项。** 用户输入「全部允许」「ok」都被当成拒绝。
   原因：rich 把提示里的 `[y=允许 / n=拒绝 / a=…]` 当成了样式标记，整段吞掉，用户只看到「允许 trash path=x ？」。
   修复：用 `Text` 对象输出提示；工具参数、结果预览、最终回答也都转义，文件名里有 `[1]` 也不会显示错乱。
   **教训：我先后两次去改“怎么判断回答”，都没有先在真实终端里看一眼提示长什么样。改交互之前，先看用户实际看到了什么。**
2. **试图去识别自然语言回答。** 为上面的问题做过一版「全部允许 / ok / 好的」的识别，被用户否定。
   修复：只接受 `y` / `n` / `a`，无效输入要求重输。
   教训：对确认这类安全相关的交互，固定选项比猜测意思更可靠，也更符合用户的预期。

### 测试与评测本身

3. **测试里的假模型保存的是消息列表的引用。** 主循环之后继续往列表里追加消息，断言看到的不是当时发出去的内容。修复：保存快照。
4. **空的 `.trash` 文件夹被判为“没有还原”。** undo 之后文件都回来了，但留下一个空的回收区文件夹。修复：快照不统计回收区文件夹本身。这是 checker 自检抓到的。
5. **任务本身有歧义（D04）。** 「保留文件名最短的」，可 seed 42 里有两组副本文件名一样长，模型合理地停下来等规则。修复：指令里写明并列时怎么处理。
   教训：模型“失败”时，先怀疑任务写得对不对。
6. **论文文件名泄露了答案。** arXiv 编号前缀直接用了发表年份，「按年份筛选」光看文件名就能做。修复：编号和年份脱钩。
7. **新加的标记文件改变了生成结果。** 生成器的保护标记 `.filebutler_generated` 在生成过程中就写进去了，参与了类别统计和随机数分配，同一种子生成的数据变了。修复：生成完毕之后再写标记。
8. **`placed` 被内容相同的副本骗过。** `Wang.pdf` 和 `强化学习/` 下的一个文件字节相同，`Wang.pdf` 留在根目录不动，也会被判成功。修复：查找时排除「本来就在那里的其他文件」。
9. **统计「自检修正」的口径错了。** 自检后模型只做了只读检查就核对通过，却被记成了「修正」。修复：只有执行了写操作才算修正。

### 真实数据暴露的工具 bug

10. **`list_dir` 被拦腰截断。** 51 个长文件名超过单条结果 2000 字的上限，模型看不到完整列表，只好反复调用 `list_dir` 和 `search_files`。修复：按字数分页。
11. **文件名以空格开头。** `transformer/ Exploiting….pdf` 被路径处理里的 `strip()` 去掉了空格，这个文件无法被任何工具操作。修复：原样找不到时，在同一文件夹里匹配去掉首尾空格后同名的文件，恰好一个才采用。
12. **pypdf 抽出乱码。** 一篇字体编码特殊的论文，`read_file` 返回 `ʕ ୅ͷ՝୊ ϊʔτ …`，模型只能看文件名去猜（5 次里 2 次放错）。修复：改用 PyMuPDF。
13. **连字 `ﬀ` 让 move 悄悄改名、undo 还原失败。** macOS 默认的文件系统不区分大小写，还会做 Unicode 大小写折叠，`ﬀ` 和 `ff` 被视为同一个名字。模型写的是 `ff`，文件能找到，但移动后名字变成了 `ff`，日志也记成 `ff`，undo 只能还原成 `ff` 的版本。
    修复：沙盒把路径换成磁盘上的真实名字。但 undo 如果也走这套转换，「notes.md 改成 NOTES.md」这种只改大小写的操作就撤销不了，所以 undo 改用 `exact` 模式。
    教训：设计文档早就提醒过大小写问题，但只有真实数据里的连字字符，才让它真的发生。
14. **元数据里的「标题」是排版文件名。** 有一篇论文的 PDF 元数据标题是 `PRIME No.44_03_…indd`。修复：标注脚本把这类元数据视为无效。
15. **用字号找标题时的三种干扰**：arXiv 的竖排水印字号最大；期刊名（`symmetry`、`AI Open`）出现在标题前面；同一行的词因为垂直坐标略有差异，排序后顺序错乱。修复：跳过竖排文字和页眉，同一行按水平位置排序。乱码的那篇渲染成图片后人工确认。
16. **伪粗体导致重字。** `2023.ccl-1.2.pdf` 用叠印模拟粗体，pypdf 抽出来是「基 基 基于 于 于」。修复：PyMuPDF 抽取，再看图核对。

### 机制设计

17. **用 Token 计预算是错误的口径。** 5 万总 Token 容纳不下「读 51 篇论文」的任务：总 Token 等于每轮上下文之和，随轮数平方式增长。修复：按费用计预算。
    另外：预算检查放在执行工具之后，模型最后一轮直接回答时，实际用量会超出预算（R02 用了 5.9 万 Token 仍然完成了）。这个行为保留，但要知道它的存在。
18. **压缩省 Token 不省钱。** 每两轮压缩一次，每次都让被改写位置之后的缓存全部失效（见 E6）。教训：在有前缀缓存的 API 上，「少传 Token」和「少花钱」不是一回事。
19. **测试里的假模型报告的 prompt_tokens 永远是 100。** 压缩模块用 API 报告的准确值来估算长度，测试里永远不会触发压缩。修复：让假模型按实际发送的内容报告长度。

### 开发环境与操作

20. **工具 shell 读不到 API key。** key 写在 `~/.zshrc` 里，非交互 shell 不加载这个文件。做法：调用 API 的命令用 `zsh -ic '…'` 执行。
21. **`gen` 清空沙盒时删掉过用户的数据。** 验证生成器时重建了 `sandbox/`，用户一次还没撤销的运行连同日志一起没了。后来用户把真实论文放进了沙盒，这时再执行 `gen` 就会把论文也删掉。
    修复：生成器生成的目录里放一个标记文件，没有标记、但有可见文件的目录拒绝清空（`--force` 才清空）；测试一律在临时目录里进行。
22. **花费估算偏低。** E6 预估 ¥5–8，实际花了 ¥11.3。原因：R06 一次要读 51 篇论文，单次运行就接近 ¥0.3 的预算上限。教训：用真实数据先跑 1 次，再按单次花费乘以次数来估算。

### 2026-10-18：检索、网页与运行优化

23. **把 15 张图片说成“15 个无文字层 PDF”。** 原来的 `unsupported` 计数实际表示非 PDF 文件，模型自行解释成 PDF 抽取失败。修复：明确分开扫描/索引 PDF、解析失败、前两页无词项、跳过非 PDF；保留原错误日志。教训：工具统计字段必须说明对象和范围，提示词不能替代清晰的数据协议。
24. **低分和前两页未命中被用来排除论文。** BM25 只处理词项重合，且索引仅覆盖前两页；它不能证明全文不含某主题。修复：返回页码/偏移与原文卡片，未核实项保留不确定性，明确找全任务不套普通查询预算。教训：排序分数不是相关性置信度，覆盖不足不能靠总结语气补齐；全文索引、OCR、向量检索仍未实现。
25. **“文字相同”“近似版本”“文件相同”混成一种证据。** PDF 元数据不同可以导致字节不同，相同提取文字也不能证明图表相同；附录会降低版本间 Jaccard，相邻近似关系还可能不传递。修复：分 bytes/text/similar 三档，保留全文规范化边界，近似用完整连接及短版本覆盖率，默认只回收确定重复。教训：先定义等价关系，再做自动清理；同一开发语料的诊断结果不能当通用准确率。
26. **网页照搬终端输出，长对话又滚不动。** 终端边框/参数列表不适合阅读和核对；只给消息区加 `overflow`，Grid/Flex 子项的默认最小高度仍可能把布局撑开。修复：安全 Markdown、横向表格容器、真实调用事件驱动动画，父级约束高度并设置 `min-height: 0`，消息区独立滚动。教训：真实浏览器里检查长消息、宽表格和预览；动画展示实际步骤，不冒充逐 token 输出或模型私有推理。
27. **确认页按“保留/删除”分成两堆，用户无法比较副本。** 原始路径列表丢了重复组关系。修复：由本地计划携带组成员和保留项，同组并排核对，待回收项浅红，可点击预览；关闭窗口不等于同意，确认 ID 防止旧窗口批准新操作。教训：确认应展示即将执行的真实计划，分组不能靠文件名或顺序猜。
28. **路径看起来正确，却无法预览。** 空格、括号、`#`、Unicode 和省略目录会造成解析问题；真实模型还漏写过文件名中的 `and`，改写过空格/下划线。修复分两层：旧链接仅做唯一且可验证的路径兼容，新结果改用持久 F 标识，本地生成真实名称/URL。已登记回收文件走会话专用入口。教训：名字容错不能演变成宽泛模糊跳转，文件身份不应依赖模型复写长路径；同内容副本仍需不同 ID。
29. **把确认等待算成 Agent 很慢，undo 又改变了记录更新时间。** 旧总耗时和工具耗时包含等待，数据库 `updated_at` 还会被后续撤销更新。修复：单调时钟记录运行/等待/模型/工具分项，网页等待时暂停，旧日志标明口径。教训：先测量再优化；不能用创建/更新时间差估算运行时间，也不能凭一次 34.9 秒请求断言发生网络重试。
30. **SDK 与项目层重试可能叠加。** 外层循环与 SDK 默认重试各自工作，实际尝试数和延迟不透明。修复：SDK 重试为零，只保留可配置的项目层重试，逐次记录开始/结束、错误类型、退避与用量。教训：重试责任只放一层；非流式请求总时间仍不能拆成网络、排队、生成各自的耗时。
31. **内容去重反复解析同一批 PDF。** 单次扫描计划和 `Sandbox` 生命周期短，不能自动复用前一次全文特征。修复：跨实例共享有界 LRU，text/near 复用特征，按根目录与设备/inode/大小/mtime/ctime 失效；异常不缓存，重启后重新预热。教训：缓存只节省计算，不能成为旧写计划的授权；执行前、确认后和执行后的复核仍需保留。局部扫描快 99.5% 不代表整个 Agent 同比例提速。
32. **undo 后模型还相信旧执行状态，立即撤销还可能撞上最终保存。** 文件已还原，旧对话却仍只记录“已回收”；完成事件发布与历史落库之间也有竞争窗口。修复：撤销写入实际状态事件、跳过项照实记录、幂等返回；有共享沙盒任务运行时拒绝撤销，立即撤销等待最终保存再更新历史。教训：文件状态、日志、数据库与前端完成状态必须一致，不能把副本重现误说成上次执行失败。
33. **长对话归档会丢证据，也可能损失远端缓存。** 简单截断历史会丢用户持续约定或破坏工具调用/结果配对；频繁改写前缀又会让缓存失效。修复：只在新任务入口做本地历史投影，保留全部用户指令、助手文字、写操作/撤销结果和最近完整任务，SQLite 保留原历史。教训：字符少了不等于费用必降；长期约定和近期证据都要在真实续聊中验证。
34. **提示词要求少调用，模型仍先列目录、扩 top-k、读低排名候选。** 首轮真实主题查找用了 16 次工具调用，去重先 `list_dir`，完成后还需模型总结。修复：普通查找设置本地查询/阅读预算，卡片含原文并复用重复片段；纯确定重复清理组合扫描、确认、执行、复核及本地表格。教训：确定性步骤由本地调度承担；近似、穷尽和复合任务保留通用链路，不能为了少一轮而提前结束尚未完成的用户任务。同批剩余调用也必须在结果提交后停止执行。
35. **引入证据 ID 后，模型把片段配错文件，还漏写了 ID 的最后一个字符。** 第一组错配导致重读、长对话变慢；第三组笼统报错又让模型误删 E 前缀，最终未核实结束。修复：严格校验文件归属/版本，一次列出所有错配文件已提供的有效 E 标识，要求原样选择，不自动猜补。原失败现场真实重放仅一次提交就修正。教训：短 ID 也可能被抄错，报错要给具体、可执行的恢复信息；有 ID 仍不等于自然语言结论必然被证据支持。
36. **假模型浏览器检查全过，真实模型仍暴露策略与语义问题。** 协议替身能走通 UI/HTTP/确认/undo，却不会自主扩大检索、改坏路径或作超范围结论。修复：分别记录离线工程检查与真实模型检查，授权后用临时语料、独立服务/数据库/Chrome 跑真实流程，并逐链接审计。教训：首个 PDF 可打开不代表所有引用都正确；工程通过率不等于语义正确率。
37. **失败回答更快，会把性能中位数“优化”得很好看。** 三组对照的新版主题查找有一次 8.98 秒的失败；全尝试中位为 10.42 秒，成功项中位实际为 12.97 秒（仅两次）。修复：同时报告成功数、失败原因、成功耗时及对照条件，失败现场和恢复复验单列。教训：速度必须与质量一起看；长对话中位 17.24→18.06 秒就应如实记为尚无稳定提速，不能只挑 9.95 秒的快例子。
38. **验收脚本点击“首个引用”，选到目录而非 PDF。** 首版对照因此等不到 PDF 预览，不是产品的 PDF 渲染故障。修复：选择带 `data-file-kind="file"` 且后缀为 PDF 的引用；保留中止报告及已花费用 ¥0.02633416。教训：自动化选择器要表达正在验收的对象类型，测试脚本的错误与产品错误分别归因，中止实验也要计费。
39. **离线审计曾把所有新 ID 都判成失效。** macOS 临时目录的 `/var` 与 `/private/var` 指向同处，但字符串不同；审计重绑根目录时未 `resolve()`，触发标识仓库的根目录隔离，清空了审计副本的映射。清理后的回收路径也不能直接在原始可见语料里找到。修复：规范化临时根目录；只在审计临时副本中按原文件名和 SHA256 重建已登记的回收文件，再校验引用，不修改原数据库或放宽产品隔离。教训：审计器本身也要核对；区分路径拼错、文件已回收、版本失效和审计重建错误。

## 三、当前边界

### 功能

- **能读的内容**：txt、md、csv、json、log、yaml、py，以及 PDF（默认前 2 页，也可指定单页）；默认返回 1500 字，启用文件/证据标识时单次片段最多 1600 字，旧模式最多 1800 字，支持 offset 续读。docx、xlsx、pptx、图片的内容都读不了，图片只能看文件名、大小、MD5 和 EXIF 拍摄日期。
- **主题检索**：`search_content` 仅索引 PDF 前两页，英文词切分/中文二字切分；返回页码、偏移、原文候选证据。缓存属于 Sandbox 实例，每次查询检查路径清单和 stat 指纹；不写缓存文件，不索引隐藏目录、回收区和符号链接（含沙盒内链接）。分数不是置信度。无词项重合会漏检，泛化词会带来误候选；51 篇 × 12 查询诊断中跨语言两个查询全漏，E12 端到端 API 对照待做。
- **查找速度**：`v2_search`/`v3_local` 规则由当前默认 `v7_classification` 继承，先检索、按需核实，避免递归查询后又列所有目录；普通主题任务由本地策略强制使用含原文的 `view=evidence`，工具/CLI 原有 `compact`、`detail` 模式保留。
  完整姓名可用 `match=all` 过滤部分词命中，仍需核对作者，不能当作结构化作者字段。此过滤可能漏掉别名/缩写，主题查询默认仍用 any。
  新增逐轮模型请求耗时；两条终端查询各两次实测变快，但尚无全任务回归的真实 API 结果。
- **批量去重已实现**：`find_duplicates` 本地批量字节哈希/PDF 全文比较；`apply_dedup` 一次执行多个副本回收、逐文件记日志。明确授权的纯确定重复清理可由 `deduplicate` 一次调用完成扫描至最终结果，默认近似版本仅报告。
  规范化相同指提取的文本相同，不代表图表/图像相同；近似基于文本 shingles，不声称识别任意语义改写。只保留最近 3 个内存扫描计划，执行前复核指纹。
- **移动和改名仍逐文件**：没有 `move_many`，300 个文件就要 300 次 move 调用（E8 未做）。
- **检索统计不能由模型改义**：旧报告中“不支持 15”实际是 15 个 JPG，模型曾写成“15 个无文字层 PDF”。工具已把字段改为“跳过非PDF文件”，并分别报告 PDF 失败/前两页无词项；`v4_evidence` 要求准确引用，不能根据低分直接排除主题。前两页范围仍是功能边界，不自动扩大为全文或 OCR。
- **重复调用检测已实现**：同一工具和 JSON 参数连续第 2 次提醒、第 3 次拦截并中止（`repeated_call`）；默认开启，可通过 `repeat_detection: false` 关闭。
  按调用顺序计数（含同一批调用），不同工具或参数重置；忽略 JSON 键顺序及空白，不补默认值、不做路径容错匹配。
  中止后跳过同批后续调用并补齐工具消息，已有写操作保留日志、可 undo。代价：相同参数的合理轮询也会触发；A/B 交替循环不会触发，仍靠步数和预算兜底。
  已有离线回归覆盖，E5 真实 API 对照尚未做。
- **还没有实现**：`ask_user` 反问工具（遇到有歧义的指令只能靠模型自己猜）、ReAct 模式（E3）。
- **本地 Web MVP 已实现**：FastAPI、多会话、流式步骤、Markdown、文件预览、分组确认及 undo；仅绑定本机。不能操作沙盒以外的文件。

### 规模与成本（deepseek-flash，高峰时段价格）

| 场景 | 每次运行 | 耗时 |
|---|---|---|
| 普通单步、多步任务 | ¥0.005–0.02 | 3–15 秒 |
| 300 个文件分 6 类（B10） | 约 ¥0.22 | 约 100 秒 |
| 51 篇论文全部重新分类（R06） | 约 ¥0.26 | 1.5–4 分钟 |

- **单次运行上限**：¥0.30 预算加 25 步。逐篇阅读的任务，大约 60 篇就会碰到预算上限（按 R06 读 51 篇花 ¥0.26 推算，未实测）；上下文随轮数增长，实际可能更早。
- **十万级文件不支持**：列表分页、逐个移动、逐篇阅读在这个规模下都不可行，需要先用规则缩小范围、批量工具和检索。
- **上下文窗口**：压缩默认关闭，目前没有任务超出模型的上下文窗口；真遇到超长的任务，可以打开压缩，但会多花钱。

### 平台

- **只在 macOS 默认的 APFS 上测试过**（不区分大小写）。在区分大小写的文件系统上，名字容错相关的测试会自动跳过，相应的行为没有验证过。Windows 完全没有测试过。
- 依赖 Python 3.11 和 DeepSeek API；模型名称和价格以 2026-10 的官网为准，换模型要更新 `config.yaml` 里的价格。

### 安全

- **undo 不保证一定能完全还原**：用户在运行之后自己动过的文件，undo 会跳过，不会覆盖。连字文件名的修复目前只有测试覆盖，**还没有用真实 API 重跑验证**。
- **注入测试覆盖有限**：注入只放在文件正文里测过（合成数据 F01、F03–F05），模型 0 次照做；注入写在**文件名**里的情况、真实数据里的注入，都还没有测试。
- **确认机制有盲区**：`risky` 模式下，10 个文件以内的移动和改名不会询问，只能依靠 undo 兜底。
- **符号链接**：指向沙盒外的一律拒绝；指向沙盒内的，按代码逻辑可以正常使用，但没有专门测试过。

### 评测

- **真实数据很少**：一个数据集（51 篇论文）、6 个任务、每个任务 5 次。差异在 1–2 次以内的，可能只是噪声。
- **标注只有一个标注者**（Claude），分类按「方法」而不是「研究对象」，有边界案例（比如 *A Different Kind of Viral Threat*，这篇保留了用户原来的 covid-19 归类）。
- **结果版本不一致**：R01–R03、R05 是在换用 PyMuPDF 之前跑的；合成数据 37 个任务的 95% 是在旧的 Token 预算下跑的，都还没在当前版本上重跑。
- **temperature=0 仍有随机性**：同一任务重复运行，结果可能不同（C05 的漏文件大约 1/70）。
- **断言只看最终状态**：多余但无害的操作、绕远路，只体现在步数和费用上，不会被判为失败。

### 工程

- **代码量超出原定目标**：核心约 1050 行（原定 300–500 行），主要多在安全层的名字容错、成本统计、自检和压缩。
- **许可证**：PyMuPDF 是 AGPL-3.0；中文字体 Noto Sans SC 是 OFL，首次生成合成数据时自动下载，不进仓库；论文 PDF 有版权，不进仓库。

### 2026-10-18：长耗时的逐项修复

此前 `seconds` 和工具 `ms` 混入确认等待，undo 还会更新运行行的 `updated_at`；不能用数据库创建/更新时间差判断 Agent 运行速度。现保留总耗时并新增运行、等待、模型和本地工具分项；旧日志不改写。模型请求记录逐次开始/结束与重试，避免把“34.9 秒总结”无证据归因为网络或重试。

SDK 原有默认重试与封装四次尝试可能叠加；现在只有项目层，默认最多两次请求。可配置超时与重试次数。没有用额外模型调用判断是否该重试。

PDF 全文提取/规范化/特征由本地 LRU 缓存复用，跨会话和查重模式生效。新扫描仍遍历目录、检查文件状态，清理仍校验 SHA256；缓存不是写操作授权，也不让旧计划跨任务直接执行。缓存重启后失效，近似两两比较仍为平方复杂度。

撤销实际结果同步进入对话，不能把用户撤销后重现的文件当作上次执行失败。历史补录保留事件时间，避免把过时撤销误当当前文件快照。运行期间不接受撤销，防止与任一对话的共享沙盒任务交错。

长对话只在新任务入口归档旧工具交换，完整对话仍保留给 UI。保留用户约束、助手文字与写操作/撤销结果，最近两个任务保留完整工具证据；不为压缩再请求模型。归档会影响远端前缀缓存和旧证据可用性，不能仅凭字符减少就声称成本一定下降。默认逐轮压缩仍关闭。

### 2026-10-18：文件标识、证据收尾与组合清理

真实验收暴露的三类问题已落实为默认 `v6_runtime` / `local_runtime: true`。文件 F 标识在 Web 会话持久化，当前会话经日志记录的移动/回收及 undo 更新位置；版本或外部改动使旧引用失效。已登记的回收文件走会话专用预览入口。模型无需复写长路径，普通主题表格和确定重复回执由本地生成。旧路径历史继续兼容，原来错误的引用不自动改写。

片段 E 标识绑定文件、版本、页码和偏移；`report_findings` 拒绝证据错配、过期和无查重依据的全文等价判断。真实三组复测发现一次漏写 E 标识末字符的失败；报错现同时给出涉及文件已提供的有效片段，帮助直接纠正，不静默猜测。修复后原失败现场真实重放一次提交成功，新增确定性回归覆盖。证据归属/范围约束不是自然语言语义证明器，说明文字仍可能越界。

普通查找最多两次查询、五次片段读取，原文卡片足够时直接提交，重复片段本地复用。确定重复清理的 `deduplicate` 组合本地扫描、原有确认、逐项留日志、复核与最终结果，不额外调用模型总结；近似版本和显式找全/复合任务保留通用链路。意图分流使用本地关键词，复杂措辞可能分流不理想。

最终离线 265 项测试通过，真实四场景复验 32/32；三组对照的内容清理净运行中位 13.34→7.50 秒，undo 后重做 6.70→3.07 秒，两类任务各从 3 次模型请求降到 1 次。长对话中位 17.24→18.06 秒，尚无稳定改善，不承诺所有任务提速。完整设计/边界见 [本地策略 V1](runtime-optimization-v1.md)，数据见实验记录。

### 全量分类与批量执行补充

最新两轮实际任务是全量核心方法分类和移动，不是普通主题查找/去重，因此原 `v6_runtime` 的专门预算没有接管；两轮模型请求分别占净运行约 98.1%/97.6%。分类最后一次长清单请求耗时 32.14 秒，第二轮仍带 11 万字符历史并用四轮模型编排移动。仅优化 PDF 解析或增加向量数据库，不能直接消除这些往返。

当前默认 `v7_classification` 增加批量论文卡片、持久 P 计划与本地生成表格，普通分类最多六次成功补读；明确执行分类计划时零模型请求，完整确认、逐文件日志及 SHA256 复核都保留。执行上下文只投影计划和约束，完整历史仍保存在数据库。泛指“执行这个计划”不走分类快捷执行，避免误用较早的分类计划；复杂指令仍交模型处理。

复测踩坑：模型会把完整 F 标识当文件路径，现支持精确解析已登记裸 F 标识；类别“自监督/半监督”里的 `/` 不是目录授权，改由本地转全角目录字符，避免整份计划重提；六次补读预算耗尽后仍允许补完未读目录卡片，不能因关闭工具而丢文件。目录创建也需逐项记录，部分失败只报告实际完成项；目标独占创建避免覆盖，源位置被占用时不强行回滚。

两轮真实 46 篇副本验收均为 14/14，执行净运行约 0.36/0.37 秒、模型请求 0 次，undo 完整还原；第二轮分类为 36.70 秒/6 次请求。最后的类别转换以原失败参数本地重放验证，未混入真实性能数据。最终离线回归 282 项、旧 Chrome 协议验收 32/32。类别数和语义判断仍可能变动，片段缓存不是分类正确性证明，也没有实现完整增量分类器。详见[分类优化 V1](classification-optimization-v1.md)。
