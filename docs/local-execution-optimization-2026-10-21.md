## 参考与取舍

- [Local-File-Organizer](https://github.com/QiuYannnn/Local-File-Organizer/blob/main/data_processing_common.py)：借鉴 compute_operations/execute_operations 分离；不采用其链接文件的语义，也不沿用固定前三页作为穷尽证据。
- [Terraform](https://github.com/hashicorp/terraform/blob/main/internal/backend/local/backend_local.go)：借鉴保存计划、绑定原状态、拒绝过期计划；不引入 Terraform 作为依赖。
- [LangGraph](https://github.com/langchain-ai/docs/blob/main/src/oss/langgraph/interrupts.mdx)：借鉴检查点和中断恢复；仍使用现有 SQLite，不迁移框架。恢复可能重跑节点，因此必须自行处理写入幂等性。
- [PydanticAI](https://ai.pydantic.dev/tools-advanced/)：借鉴确认前校验及有界修复。当前使用现有 Pydantic 和机器错误码，不新增整个 Agent 框架。
- [Paperless-ngx](https://github.com/paperless-ngx/paperless-ngx/blob/main/src/documents/models.py)：借鉴持久正文与内容版本。当前先做内容寻址的解析缓存；尚非完整跨会话文档资产库。

## 模型与代码的边界

模型负责理解用户目标、选择对象、分类与语义判断。新普通文件任务可直接调用 prepare_file_plan，不必先手填来源/目标选择器、父目录操作和验收契约。本地程序编译具体清单，再通过 execute_file_plan 的一次确认执行。

已有任务必须沿用原任务的范围、副作用和约束。准备计划不会自动扩大它们；不满足时拒绝并给出具体对象。复合任务使用明确 goal_ids，执行器在调用边界绑定目标，不依赖模型维护全局步骤游标。任务新建时推导的精确路径仅为权限需求；实际执行仍须沙盒、确认策略与操作日志。

分类仍由 paper_profiles / submit_classification 完成。新分类执行任务可调用 prepare_file_plan(classification_plan_id=精确P标识)，本地展开原计划，不让模型重抄全部路径。由此建立的任务强制 semantic_review=true。已有任务不另建任务绕过限制，旧 apply_classification 仍兼容。

## 新协议

- prepare_file_plan：description、actions 或 selection，或精确 classification_plan_id；已有复合任务提供 goal_ids。
- actions：create 的 destination；move/rename 的 source 与完整 destination；trash 的 source。source 可用当前对话有效 F 引用。
- selection：path、extensions、exclude_paths、recursive、effect、destination、preserve_tree，本地枚举完整选择集。不同目标可提交明确 actions。
- execute_file_plan：只接收精确 X 标识，不接受 latest；显式恢复也用同一标识。
- inspect_file_plan：只读返回清单、状态、已完成数量和阻塞原因，不授权执行。

编译器生成缺少的父目录、具体操作、源对象 stat/SHA256 快照、任务/版本/目标绑定以及计划摘要。计划存于当前资料库的 TaskStore SQLite，并按资料库/会话隔离。普通模型工具结果只返回 ID 与数量，长表保留在本地展示记录。

自动生成任务使用 file_plan_verified 条件，执行与核验共享同一清单，不能因目录中还存在未选中的其他文件而误判失败。核验检查目标内容、对象身份和原位置，创建目录另检查身份；撤销或执行后内容变化会使核验失效。已有任务的原条件不会被自动替换或降低。

## 预检、确认和失败

1. OperationRule 拒绝 create/source、trash/destination 等不可能的路径规则。outside 不再让缺少路径的操作空通过。
2. files_placed 等执行前快照只要出现错误，登记、编辑预览和应用都拒绝；旧记录写入前也重查，不能执行后才发现验收依据无效。
3. 新计划先检查来源、目标冲突、隐藏项、符号链接、同名/Unicode 折叠冲突、依赖循环、范围、约束与数量，再请求确认。
4. 用户确认绑定计划 ID、摘要和具体步骤；确认后、每项操作前均重查。新 Web 确认支持来源预览、目标展示与回收项标记。
5. 新执行器使用系统的原子禁止覆盖移动：macOS renamex_np(RENAME_EXCL)，Linux renameat2(RENAME_NOREPLACE)。不支持的平台拒绝，不退回可能覆盖目标的 rename。
6. 日志每项写入后 flush/fsync。计划执行前先保存 inflight 意图，逐项保存已完成进度。跨资料库进程的同类新执行器通过文件锁串行化。
7. 中断发生在确定未修改前，可在重新预检和确认后继续；日志中的 action_id、源位置、目标 inode 和哈希一致时，可恢复已完成文件操作，补齐账本而不重放。仅“目标存在或内容相同”不足以自动恢复。创建目录或其他结果不明的窗口仍停下，明确提示核查；不宣称文件系统与 SQLite 是一个原子事务。
8. 已完成计划再次调用只重核验，不重复修改或确认。部分计划续做保留前轮日志和数量用量，本轮仅执行剩余步骤；撤销仍按各运行日志进行。

失败正文展示实际本地阻塞原因；模型的必要补充解释在失败/待输入正文中标注“模型说明”，不能冒充确定性证明。历史恢复后的失败不应据此改成成功。

## 减少无效往返

- 分类或批量文件计划形成后由本地循环执行，不逐文件询问模型。
- 保留原始相同调用保护，新增 task_repair_limit（默认 6，0 关闭）：同类写入/协议错误在没有执行或新证据进展时累计达到预算即停止，后续排队调用也不执行。按机器错误码计数，不解析中文词语；修改任务字段或轮换路径不自动重置预算。
- 当前步绑定只在所服务目标、相关约束、权限和语义偏好均未变时保留；改变其他目标或输出格式不会无条件清空，修改相关权限仍失效。
- 本地编译任务的近期上下文只传范围数量、有限样本及计划 ID，完整权限继续由本地保存和强制检查。

## 跨运行解析缓存

.oplog/document-cache.sqlite3 保存 PDF 文字层解析结果，键由原文件 SHA256、开始页、页数/全文、解析器版本和缓存协议版本组成。读取、分类卡片和 BM25 共用；文件移动、相同内容副本和新对话可复用，内容或抽取范围变化则重新抽取。会话文件引用、证据和授权不共享。

解析失败不缓存；抽取或缓存读取期间文件变化则拒绝。缓存不可用时回退正常解析，不能把缓存问题当文档没有文字。单条超过 1600 万字符的结果不持久缓存，但不截断正常解析结果。运行统计 document_cache 提供 hits/misses/unavailable。

这不是向量索引，也不替代 OCR；默认前两页的证据范围保持可见，不能宣称检索穷尽。完整文档目录、长期位置同步、OCR、全库持久 BM25/向量召回仍是后续独立工作。

## 验证与限制

新增真实临时文件测试覆盖计划编译、选择集、一次确认、重复执行、undo、源/目标/版本/符号链接竞争、原子禁止覆盖、已有权限不扩张、读取范围、跨会话隔离、快照拒绝、崩溃恢复、部分续做与历史账本、分类桥接和语义复核、依赖敏感的步骤绑定、不同参数失败预算，以及缓存跨运行/移动/版本/范围复用和失败回退。

脚本模型端到端测试证明两轮模型响应可以完成“本地展开选择集—准备计划—执行—收尾”的多文件流程，不代表真实模型必然选择此路径，也不代表固定的真实延迟下降。

尚存边界：

- 新执行器锁尚未覆盖全部旧分类、去重和直接文件写工具；旧路径仍保留原有逐项校验。不能宣称全应用已经实现跨会话统一事务。
- 当前通用计划处理普通文件、创建目录和回收空目录；非空目录移动、覆盖、互换、循环依赖要先拆成明确阶段，不隐式处理。
- 不保证从每一个崩溃点自动恢复；无法证明的状态交给核查，日志写失败后的不明确动作不会自动重放。
- 复杂语义约束、歧义和用户意图仍由模型判断/用户复核。新路径不会自动将文本约束编译成权限。
- 本轮未新增真实付费模型或浏览器现场验收；此前真实验收未通过的结论不改写。需要用新盲测验证模型是否使用简化协议、实际请求数、费用及任务理解准确性。

最终离线结果：434 passed，7 项既有依赖弃用警告，38.61 秒；新增 28 个实例。Python 导入/编译、前端脚本语法和 git diff --check 通过。新执行器在确认期间也持有自身资料库锁，其他同类执行会快速拒绝；当前不是并行执行队列，也不是全应用统一事务。
