# 策略重构：不变量、任务偏好、模型判断与本地事实

后续实施：2026-10-21 的[本地计划执行优化 V1](local-execution-optimization-2026-10-21.md)新增通用计划、预检、有界修复和解析缓存；以下历史描述以对应交付时点为准。

后续进展：同日已执行[真实模型验收](live-acceptance-2026-10-20.md)，发现尚未通过项。本文末尾的未调用付费模型描述仅指重构交付时的验证范围。

日期：2026-10-20。适用于默认 `task_runtime: true` / `prompt: v8_tasks`。本记录描述本轮实现，不代表架构 V2 后续阶段全部完成。

## 决策边界

| 问题 | 决策者 | 验证依据 |
| --- | --- | --- |
| 路径权限、允许副作用、是否需要确认 | 本地沙盒、任务范围与调用方确认策略 | 操作前检查，执行器确认后重查，记录真实操作 |
| 版本、文件内容、数量与预算 | 本地程序 | 版本、哈希、执行前清单和持久计数 |
| 用户目的、指代、语义标准、任务拆解与重规划 | 模型 | 保留原始请求和结构化目标；语义结论不能冒充确定性事实 |
| 目录结构、编号、抽取页数、格式与详略 | 任务参数，模型依据用户要求填写 | 参数校验与差异预览；不能自行扩大权限 |
| 文件当前的位置和内容是否满足要求 | 本地程序 | 当前文件系统和版本化证据，不能根据回答措辞认定成功 |

资源上限、机器协议和受保护目录仍由代码定义。可调整的偏好不能绕过这些边界；新增能力须注册具体安全适配器，不能让模型提交任意代码充当检查器。

## 任务、步骤、授权、证据分别表达

运行流程为：理解请求 → 必要调查 → 登记任务 → 指明步骤 → 本地检查与执行 → 观察结果 → 调整后续步骤 → 核验目标。同一轮可依次调用 `set_task`、`begin_step` 与工具，不增加一次专门让模型写计划的往返。

`TaskSubmission` 保留目标、条件、范围、副作用和约束，新增 `policy`：

```json
{
  "criteria": ["按用户给出的业务标准判断，证据不足保留不确定性"],
  "evidence": {"pdf_pages": 2, "excerpt_chars": 600},
  "output": {"format": "markdown", "detail": "concise"}
}
```

`pdf_pages` 为正整数时抽取前 N 页，显式 null 抽取全部文字层。输出支持 markdown/text/json，以及 concise/full。策略是偏好，不赋予许可，也不证明模型理解正确。续做未提供的策略保持原值，修改已有策略通过编辑预览与确认。

`begin_step` 登记 `{id, goal_ids, description}`，与任务契约分开。步骤 ID 的含义不能重写，重规划使用新 ID。复合任务写入必须指明相关目标；单目标自动归属唯一目标，减少控制调用。

`Constraint.goal_ids` 为空表示全任务，非空仅约束对应步骤，全局禁止始终生效。空目录回收保护只用于空目录目标的步骤，因此不再禁止另一个去重目标合法回收副本。步骤用途仍由模型解释，本地不会声称能证明每个步骤的语义都符合用户意图；实际写入继续受范围、副作用、版本和确认策略约束。

观察、引用和操作记录附带目标/步骤标识。条件引用留空时只选择对应目标产生的对象；同一目标存在多个分类计划时拒绝猜测，必须明确 reference。多个片段或回执可用于同一目标。旧多目标任务的无归属引用不自动猜给某个目标，须明确引用。

阅读/检索 `usage` 跨续做和任务编辑保留。实际发出的失败调用也计入次数，准备阶段拦截的不计。`max_count.count_scope` 明确为 task/run，新规则默认 task；任务操作历史跨版本保存，批次新增日志也参与检查。旧字典未声明 count_scope 的规则保持原 run 含义，无归属的历史操作按保守口径计数。

## 能力契约

`Tool` 注册位置声明 `read_scope`、`write_scope`、`operation_preview`、`path_fields`、`file_fields`、`usage` 和 `reference_inputs`，适配函数位于 `tools/scopes.py`。任务控制器不再通过工具业务名称推断文件范围或操作含义。

缺少范围适配器的能力不能在受约束任务中静默通过。简单写能力须有操作预览；批量执行器继续逐项调用约束检查。工具可原生返回 `ToolResult(status, text, error_code, retryable)`，控制逻辑及事件状态读取结构化 status。旧字符串工具只在注册层保留兼容转换，尚未全部迁移为原生结构化结果。

## 当前能力的参数化

分类工具新增 dimension、base_dir、numbered、category_paths。V2 默认沿用来源目录且不编号，不自动增加“按方法”层级；类别可映射为显式多层目录。secondary_categories 表达附加标签，实际移动仍使用主 category，不自行复制文件。

目录别名碰撞、目标重名、越界、隐藏路径、符号链接和版本变化继续拒绝。历史计划保留原布局，显式 legacy 控制器保留旧默认值，不能偷偷修改已确认方案。

卡片继承任务抽取策略，缓存同时匹配版本和策略。同一目录快照不混用策略，快照保存当时提供的卡片依据。当前专用批量分类仍仅支持 PDF、最多 500 份/30 类和完整快照提交，尚无增量草稿；通用任务控制本身不按论文/照片等词路由，可组合现有通用能力处理其他格式。

BM25 按任务策略或本次 pdf_pages 抽取更多页/全部文字层，缓存纳入抽取范围。证据视图实际使用 page 分页，候选不会被暗中截成前五项。每页是有界片段，全文抽取在本地，不会全部发送给模型。read_file 未指定页时继承任务策略，指定页时只读该页，缓存区分覆盖范围。

参数标准化保留“未填写”和“显式 null”的差别：用补全默认值的参数检查范围，但向能力传递保留字段是否填写的信息，避免继承策略意外变成全文抽取；观察记录也保留调用者实际提供的参数。

report_findings 的 relation 改为任务标签，兼容旧标签。移除中文肯定/否定正则作为事实判定的做法，解释统一显示“模型判断（待复核）”，引用只证明出处和版本。claim_type=byte_identity 要求其他文件标识，由本地重新计算 SHA256、核对版本并生成事实文字。解释文字不会获得确定性核验标识；程序没有尝试靠另一套关键词证明模型绝未夸大结论。

普通解释或讨论可直接回答，返回 answered，不强迫建立伪文件任务。inspect_run 默认只读结束，复合请求可 finish=false 查询后再处理明确请求的工作，查询本身不恢复任务或授权写入。

网页编辑目标文字保留机械完成条件，并要求复核含义是否一致；编辑预览展示约束目标范围和本地规则。Web 使用配置的提示词，与 CLI 一致；V8 不再继承 V5 的论文查找默认规则。

## 完成条件：当前状态与执行事实

evaluation=current_state 是默认：收尾重新检查路径、内容、证据或计划位置。文件移出约定目标后，该条件应失败，不能只沿稳定 ID 跟到任意位置便算完成。

evaluation=execution_fact 仅支持有本地回执的 plan_applied/receipt_verified，只证明记录中的执行曾通过，不声明当前位置。后续重命名或重组需另列最终位置条件；不能自动把旧当前位置条件改为历史事实来消除 partial。

files_placed 支持 flatten（原名归集）、preserve_tree（保留相对层级）、mapping+placements（完整最终路径映射，支持改名）。均使用执行前清单和 SHA256。映射不得遗漏或混入文件；名称交换允许原路径成为另一文件的最终目标，仍须逐目标核对内容。兼容新默认字段不会导致续做时丢失原清单并重新采样。

本轮未重新操作用户此前的 126 篇论文，也未追改旧任务强行消除 partial。历史静态位置条件与最终需求不一致时，应通过具体任务编辑说明新契约，再核验。

## 验证与边界

新增临时目录与脚本模型测试，覆盖录音去重和空目录组合、CSV 保留层级/改名、名称交换、跨轮数量预算、查询与执行组合、领域分层分类与多标签、第三页召回与证据翻页、中英文解释、JSON 输出、新能力接入和原生结构化错误。

原有三轮复合任务添加步骤控制后仍是三轮模型交互，不代表真实延时/费用已经测得下降。目标数量评测改名 goal_count，不再称语义目标覆盖率；新增精确 rule_contracts 检查。旧分类零模型验收明确固定 legacy V7，基线同时关闭 task_runtime，避免两组实际使用相同控制器。

真实模型理解率、语义分类准确率、耗时和费用仍需独立验收，本轮未调用付费模型。尚未新增 OCR、向量数据库、持久文档库/全文索引、通用幂等执行恢复、增量分类草稿、可扩展完成谓词注册。全页抽取不等于模型通读，也不保证语义检索穷尽。

最终本地验证：全量 **403 passed**、7 项既有弃用警告，35.37 秒；较上轮新增 24 个测试实例。两个前端脚本语法、Python/YAML 解析及 `git diff --check` 均通过。未进行付费模型或浏览器现场测试，因此不报告真实理解率、费用或耗时改善幅度。
