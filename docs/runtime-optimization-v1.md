# 本地执行与证据约束 V1（2026-10-18）

本轮对应真实验收中的三个问题：查找/清理往返过多、模型重写长文件名导致预览失败、依据局部片段断言全文相同。该轮启用 `local_runtime: true`、`prompt: v6_runtime`；当前默认已升级为继承这些规则的 `v7_classification`，新增流程见[分类优化 V1](classification-optimization-v1.md)。BM25 仍检索 PDF 前两页，没有扩大为全文索引、OCR 或向量检索。

## 1. 文件引用交给本地生成

`agent/artifacts.py` 给每个文件分配不含路径的 F 标识，记录沙盒根目录、真实路径/名称、文件状态指纹和 SHA256。同内容的两个副本仍有不同标识。

检索/阅读返回 `file:F…`，模型后续可直接用该标识读取文件。主题结果和查重回执由本地渲染真实名称与 Markdown 引用，不再要求模型复写完整长路径。网页把经过校验的标识转换为蓝色文件按钮；证据引用定位到 PDF 对应页。

Web 会话的标识保存在 SQLite `conversations.artifacts_json`，启动时自动补列。新链接在刷新、重启后仍可解析。当前会话中经操作日志记录的移动/回收更新引用，undo 后恢复；已登记的回收文件只允许通过该会话的专用预览入口读取。普通文件接口仍不能浏览隐藏回收目录，也不能用别的会话的标识打开文件。

外部改动、未登记的移动、版本变化、符号链接或沙盒越界会使引用失效，不搜索相似名字替代。其他会话执行的移动可能使本会话旧引用失效，需要重新检索。旧历史里的路径链接继续兼容，不能自动修复原本不存在或有歧义的路径。

## 2. 结论绑定证据

原文片段登记 E 标识，绑定文件 F 标识、内容版本、页码、偏移和范围。普通主题查找以 `report_findings` 提交结构化结果；本地核对证据存在、文件归属和当前版本，拒绝错配或过期证据，然后生成文件/关系/依据表格，本轮结束。

关系包括方法相关、综述入口、片段中提及和尚不确定。不确定项采用本地措辞，不把低分或未入选当作已排除。表格固定说明：检索仅覆盖前两页、结论基于片段、不能保证穷尽、不能证明全文或字节相同。未经本地查重支持的全文等价说法会被窄规则拒绝。

字节 SHA256 相同、全文规范化文字相同和经确认的近似版本，是不同的查重证据。清理产生独立 R 回执，本地记录实际移动数、保留文件、组成员、扫描范围及复核结果，不让模型重新编写执行事实。

这是证据归属/版本/范围校验，并非通用语义证明器。`reason` 与 `note` 仍可能包含不被片段充分支持的自然语言结论；需要持续审阅真实结果。错配或缺字的 E 标识会一次列出涉及文件已提供的有效片段标识，要求原样选择并重新提交，不模糊匹配或静默换证据。连续两次结构化提交失败会如实结束为未核实，不把失败回答算作验收成功。

## 3. 控制往返，把确定性工作放本地

- 普通主题查找首次最多 5 个候选，最多 2 次查询、5 次必要片段读取。首次有命中后，补充查询需标注 `retry_reason=insufficient_evidence`。证据卡片已含原文，不要求每项再读一遍；相同版本/页/偏移/长度的阅读复用 E 标识。
- 达到预算后仅接受结果提交，未核实项保留不确定性。显式找全、逐篇核实和复合写任务继续走通用循环，避免普通查询预算截掉用户的完整任务。
- 明确授权清理的纯确定重复任务可调用 `deduplicate`，一次执行本地扫描→分组确认→批量回收→执行后复核→最终表格。取消后原样保留；部分失败按实际已移动数报告，保留 undo 日志。同批后续调用不能在结果已提交后继续改文件。
- 只要求查重/报告的任务不开放组合清理；近似版本沿用 `find_duplicates`→`apply_dedup` 分阶段确认。含分类、改名、生成报告等复合任务不会在完成去重后提前结束。
- 文件不存在等错误才开放目录导航作恢复，正常清理无需先 `list_dir`。仍保留 SHA256 执行前/确认后复核、安全沙盒、逐文件操作日志和共享全文缓存。

意图分流使用保守的本地关键词规则，不增加分类模型请求；复杂自然语言仍可能分流不理想。预算不等于固定两轮请求：必要阅读、一次补查、提交修正和模型重试仍会增加轮数。

## 配置与使用

```yaml
local_runtime: true
prompt: v6_runtime
topic_query_limit: 2
topic_read_limit: 5
```

更新后重启 FastAPI，再刷新网页。旧会话下一次发送时补充新规则，完整历史不改写。关闭本地策略作对照时同时使用 `local_runtime: false` 与 `prompt: v5_latency`。

Web 引用持久化；CLI 的标识限当次运行。证据/回执存储当前未做容量清理；大规模长会话后续需迁移为独立索引。正文的语义判断仍由模型完成，全文文本相同也不证明图表和版式相同。

验收在临时语料副本、独立 localhost 服务和无头 Chrome 上运行，不改用户沙盒。真实对照交替运行新/基线各 3 次；基线是当前代码关闭本地策略、使用 v5 提示词，不是完整旧版本 checkout。性能结果见实验记录，不能由单次耗时推断稳定加速比例。

最终代码离线回归 265 项通过；真实四场景复验 32/32 通过。三组对照中曾有一次主题查找因模型漏写 E 标识字符而失败，已保留失败报告；完善纠错提示后，原失败现场的真实模型重放用一次结果提交修正成功，没有重新检索或读取。长对话尚未显示稳定提速。
