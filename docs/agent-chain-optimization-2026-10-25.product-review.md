## 2. 审核清单

| 审核项 | 通过标准 |
| --- | --- |
| 问题真实存在 | 分开标注代码确认、离线复现、历史实测、待验证推断；局部清空未回答问题的复现不能扩大成已越权执行结论 |
| 交付价值和范围 | 优先减少当前可复现的错误结算、重复恢复和错误覆盖统计；明确已实现能力、补缺口、延后能力 |
| 完整链路 | 接收/幂等 → 输入关系 → 提问/回答 → 任务/目标 → 检索/证据 → 计划/确认 → 执行/恢复 → 核验/报告 → UI/评测均有边界与验收 |
| 选择和授权 | 回答只解决有确切身份与范围的问题；选择不等于文件权限；未知问题归属不能整批清除或凭文本猜测 |
| 取消与暂停 | 取消停止剩余工作、保留已发生事实；暂停仅显式恢复，不能由普通新请求暗恢复；拒绝、超时、中断不能自动重弹同一清单 |
| 局部跳过 | 目标级 skip 与对象级 skip 明确区分；后者未实现不能宣称覆盖；范围未知保守等待，不结算其他目标 |
| 重试与崩溃 | 同一消息只接收一次；已完成操作不重做；unknown/inflight 先核对，不能凭同名同内容目标认定成功；不同错误恢复方式分开 |
| 撤销完整链路 | undo 与所有现有执行器共享跨进程资料库锁、使用原子不覆盖移动；部分撤销不能简单全量重跑，普通重复点击保留幂等，新增重试须有明确入口/attempt 身份及逐步事实 |
| 语义核验 | notes、answer、分类/相关性等语义复核保留；结构化工具结果、哈希、已读不证明语义正确或找全 |
| 检索状态与继承 | 抽取状态变化更新条目；跨请求/目标不能继承语义已核对结论；内容、抽取、查询策略等版本可追溯；无额外全量阅读 |
| 协议容量和成本 | 两种敏感配置均 ≤31,311 字符；改动逐项实测，不能删安全规则换空间；正常路径不固定增加模型调用 |
| 评测真实性 | 冻结 v3 场景/原始结果不改；v4 并列不替换退出码；新选择器/新场景另版本，缺选项不得自动选“都不动”冒充目标选择 |
| 实施可执行性 | 每片列代码入口、依赖、预算、正反例、阻断条件、发布/回滚方式；不把方案通过当实现授权 |
| 外部参考 | 官方文档/源码可追溯，提炼可落地机制；框架或新工具不能自动成为架构替换理由 |

## 3. 审核记录

待工程稿交付后填写：初审发现、修订回应、复审结果、最终文件哈希、通过范围与残余限制。

预审中独立核对 `safety/oplog.py::undo`、`webapp.py::undo_turn`、`safety/atomic.py` 与相关撤销测试：undo 当前未使用 `library_lock`，存在 `exists` 检查后 `Path.rename` 的窗口，无论跳过与否都会把日志改名为 `.undone.jsonl`；Web 的进程内 `ACTIVE_LOCK` 不等于跨进程资料库锁。已要求工程稿把原子不覆盖与共享锁纳入首批阻断级修复，并保留大小写改名、非空目录跳过、报告幂等、未知结果恢复的兼容验收。此处是源码确认；具体故障注入证据由工程稿给出，不将潜在并发窗口描述成已发生的用户数据事故。

产品审核员另行运行 `docs/repro/chain-audit-2026-10-25.py`，退出码 0，独立确认四组输出：OCR 条目仍 excluded 而 pending 计数已归零；不同 query 的 scan_id 相同；helper 层跨 request 继承 reviewed；精确回答 b 后 a+b 两项 unresolved 被清空但任务仍 partial、文件未动；undo 在已有 library_lock 时执行且确定性注入的原位占位内容被覆盖。此运行只使用临时合成文件，没有付费模型调用。

证据限制：跨 request 继承只在纯函数直接输入中复现，本轮未证明生产用户新请求可达此状态；相同 scan_id 只证明调用身份不足，不等于检索结果实际串题。问题清空证明阻塞信息/历史记账错误，不证明用户权限被绕过。撤销的确定性竞态注入证明数据覆盖窗口，不代表已发生真实用户文件事故。

撤销切片同意先交付共享锁+原子不覆盖的最小安全修复，部分撤销的显式重试与逐步恢复可后续单独实施。首片若保留现有“部分跳过后不可重试”语义，必须明确这一限制，不可声称全部已还原；不能为完整恢复状态机推迟覆盖风险修复。
