针对 `20261018-233517-228948` 和 `20261018-233636-944182` 两轮真实运行：前者净运行 58.29 秒，其中模型请求 57.19 秒；后者扣除 6.20 秒确认等待后净运行 27.96 秒，其中模型请求 27.30 秒。它们没有调用 BM25，主要瓶颈是模型编排、历史上下文和生成长清单。本轮沿用已有检索，不引入向量数据库。

## 分类流程

默认升级为 `prompt: v7_classification`，仍需 `local_runtime: true`。普通“文献按核心方法分类”使用专门流程：

1. `paper_profiles` 在本地递归枚举可见 PDF，登记版本化文件 ID，按每页 16 篇返回原文卡片。名称/原文转义，符号链接和隐藏项不进入快照。
2. 卡片选取前两页中含摘要的单页片段；没有摘要则选可提取文字较多的一页。明确显示页码和 E 标识，不假设已通读全文。片段按 F 标识与内容版本保存在会话数据库，可复用而无需重新解析。
3. 模型给出类别列表与每个文件的类别序号、`uncertain`。确实不足时可补读指定页；普通分类默认最多 6 次成功补读，独立补读应合并到同轮。明确要求逐篇核实、阅读全文或方法章节的任务仍走通用流程。
4. `submit_classification` 核对所有快照卡片已提供、每个文件恰好一次、没有额外文件、文件版本与目录清单未变化，必要的补读证据属于对应文件。不能解析的文件必须标为待核实。
5. 本地保存 P 标识计划并生成带真实文件名、预览和片段引用的完整表格，本轮立即结束，不再让模型生成长 URL 清单。

分类计划与片段缓存是不同的数据：计划保存模型的分类选择与文件版本，不代表语义判断已经被程序证明。重新分类仍可能产生不同类别；当前没有自动证明分类正确，也没有实现只重分变化文件的完整增量分类器。

卡片工具单次结果上限为 16000 字符，用于批量返回原文；其他工具仍默认 2000 字符。文件名和转义后正文分别限长，确保整批卡片不会被统一截断而误计为已提供。不能仅凭标题或目录名字把归属当作确定结果。

## 执行流程

在同一 Web 对话回复“执行这个分类计划”或“把这 N 类落成实际文件夹”时，由保守的完整指令匹配进入本地执行，**零模型请求**。复杂指令、附加要求或指定其他目标不套用这个快捷匹配。

执行使用会话中最新的结构化计划；不存在计划时明确停止，旧 Markdown 分类清单不会被自动解析为写入授权。指令中的类别数须与计划一致。默认目标是原分类范围下的 `按方法/编号_类别/`，文件名保留原样。类别中的普通斜杠本地转换为全角字符，显示标签不改义；绝对路径、隐藏项、路径穿越和控制字符仍拒绝。

`apply_classification` 在本地执行：

- 先核对每个源文件当前版本与 SHA256、目标和上级目录、重名及符号链接；已有同名目标不覆盖。
- 一次向现有确认器提交完整来源/目标清单，按分类分组，待核实项继续标注，文件仍可点击预览；确认模式 `always/risky/never` 沿用配置。拒绝时不创建目录、不移动文件。
- 确认后重新校验整个计划，再建目录和逐文件移动；每项成功立即记 oplog 并更新 F 标识位置。使用独占硬链接创建目标，再移除源链接，避免直接 rename 覆盖同名目标。需要本地文件系统支持硬链接；不支持时停止并报告，不改成覆盖式移动。
- 日志失败时尝试无覆盖地还原当前文件；原位置被外部占用时保留目标原件并报告手动恢复路径。先前已记录操作仍可 undo，不宣称整批原子成功。
- 对全部计划项复核目标存在、原位置移除、SHA256 一致，本地生成结果和文件链接。后续新增文件不自动加入计划。部分失败按实际移动/目录数报告。

Web 会话的计划随 `artifacts_json` 持久化，刷新/重启后可恢复；undo 更新文件 ID 位置，撤销后可重新执行同一计划。CLI 默认标识仓库仅限当次运行，不支持跨 CLI 进程自动恢复计划。

## 执行上下文

匹配明确的计划执行指令且已保存计划时，模型输入投影只保留用户/系统约束与紧凑计划说明，不带上一轮的几十篇原文和长回答。完整历史仍保存供网页查看。快捷执行不会调用模型，因此也不产生远端 Token 费用；复杂指令继续走原有历史与模型流程。
