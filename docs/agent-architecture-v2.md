## 目标与问题

当前模型循环已经具备调用工具、观察结果和调整行动的能力。问题在于自然语言正则同时承担了需求识别、工具筛选和授权判断；任务状态依赖聊天；部分专用工具会提前结束复合任务；执行成功和用户目标完成没有明确区分。

优化目标：用结构化任务和可组合能力处理陌生表达、复合要求及跨轮纠正；由本地程序完成确定性工作；结果可验证、可追溯、可恢复。不能承诺彻底消除模型的理解和语义判断错误。

## 总体架构

```text
聊天 / UI / API
  → Task：目标、范围、约束、完成条件、版本、来源
  → 模型按需规划 / 补充证据 / 请求澄清
  → Plan：版本化步骤及依赖
  → 能力契约与本地执行器
  → 回执、验证与任务状态
  → UI 进度与结果
```

任务与能力不绑定中文关键词、特定论文名称或固定工作流。工具标识、沙盒限制、结构化字段和验证谓词属于协议，不属于自然语言硬编码。

## 一、结构化需求与增量修改

Task 保存 id、revision、session、source_messages、goals、scope、constraints、completion_conditions、unresolved_questions、status。目标描述开放；可组合的验证谓词只表达本地能够检查的事实。

自然语言由模型登记任务，UI 明确动作可直接构造同一结构；登记和独立只读调用允许在同一次模型响应中提交。后续请求通过 task_id 与 expected_revision 更新，历史用户要求保留来源，避免把模型摘要当成原始授权。没有明确改变的约束继续生效。

重要歧义通过持久的待确认项记录；不清楚的部分不能靠猜测开展写操作。非关键歧义不应阻止独立、明确部分的工作。

## 二、需求、能力与授权分离

模型解释需求；能力契约提供输入、输出、副作用、前置条件、重试策略和验证边界；本地规则控制是否可以执行。模型填写允许写入，不等于用户实际授权。

默认 V2 路径绕过 runtime.py 的关键词分流和 local_tasks.py 的自然语言捷径，提供可组合能力。旧路径保留为显式对照模式，不继续增加同义词或语料专用分支。明确的 UI/CLI 动作仍可本地直达。

首个增量中，V2 写操作必须通过现有确认器，或由调用方显式使用 never 测试/自动化策略。没有确认器或日志时拒绝写入。完整的版本化计划授权、细粒度批量执行和跨进程恢复在第二阶段交付。

## 三、能力契约与结构化结果

沿用 tools.registry 注册表，补充能力副作用、前置条件、验证边界及重试说明。保留 dispatch 文本接口以兼容 CLI、历史测试及工具协议；新增结构化适配结果，区分本地控制拒绝、参数错误、工具执行失败和成功，不把所有异常文本声称为精确业务错误码。

首个增量的执行错误仍有一部分来自旧文本工具，标记为 TOOL_ERROR、retryable=false；细分 STALE_VERSION、TARGET_CONFLICT 等需要逐个迁移实际异常源，不能靠关键词猜测错误类型。

## 四、计划与执行

通用 Plan 包含 id、revision、task_revision、scope_snapshot、steps、依赖、前置条件、验证方式和状态。计划修改后生成新版本；确认和选项绑定具体版本，旧确认不扩大授权。

统一执行路径：预检 → 对应授权/确认 → 持久记录 intent → 文件操作 → receipt → 核验 → 更新任务。单步和批量写操作逐步接入；同一资料库写入先串行化。

每个操作使用稳定 id。重复提交按实际状态和回执处理。数据库事务不能覆盖文件系统移动；重启后必须对账源、目标、指纹和日志。部分失败、撤销冲突与状态不明分别报告，不盲目重试。

## 五、完成条件与语义边界

模型不调用工具，只表示本轮准备结束，不再自动证明任务完成。完成条件在任务登记时固定，收尾时本地重新验证；复合任务逐目标报告，专用报告工具不能提前结束全部任务。

本地验证：路径存在/不存在、目录为空、内容哈希、工具实际成功记录、有效原文证据、已保存计划、已核验执行回执。成功调用工具不等于整个用户目标已完成。分类计划保存不等于已经移动文件；证据存在不证明模型分类语义正确。

无法确定性核验的目标保持 needs_review；未完成、部分完成、待核实与等待输入分别记录。模型说明与本地核验结果分开显示。

## 六、长期文档和上下文

后续逐步建立 Document / Version / FileLocation / Evidence / Chunk，独立于聊天，兼容现有 F/E 标识。持久全文抽取、按版本增量处理、BM25 基线及解析覆盖状态优先于引入向量数据库。向量检索由跨语言和语义召回盲测决定。

完整聊天用于展示与审计；模型使用当前任务、未完成计划、相关证据、最近异常和必要用户原话。不能压缩掉原始约束，也不能破坏模型要求的工具调用/结果配对。

判断变化才调用模型；已确定文件清单交给本地批量执行。请求前检查预算，达到上限保存进度；单请求费用有估算误差，费用限制需要预留余量。

## 七、验收与阶段

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| 1：任务控制 | 结构化任务、版本与来源、能力契约、结构化结果、完成条件、默认绕过关键词路由 | 复合要求不丢失目标；不同表达不影响能力开放；模型文字不能直接结束未验证任务；约束与版本冲突受控 |
| 2：可靠计划执行 | 通用可编辑计划、选项与确认绑定、操作幂等、统一执行器和恢复 | 重复提交、中途失败、版本变化、重启及撤销冲突有明确结果 |
| 3：证据与效率 | 独立文档库、全文持久索引、任务上下文投影 | 跨会话引用、未变化内容复用、覆盖报告、相同任务费用和净耗时对比 |

贯穿评测：同义改写、否定、复合任务、跨轮纠正、陌生主题、无答案、文件变动、失败与重启。开发集和保留测试集分离，报告目标完成率、约束违反、错误完成声明、人工纠正、模型请求数、P50/P95 净耗时与费用。离线脚本模型验证协议和执行控制，不证明真实模型的理解正确率；真实模型评测另行记录。

### 第一阶段首批交付

- `agent/task.py`：Pydantic 任务协议及 SQLite 版本/检查点存储，按资料库与会话隔离；保存本地取得的原始用户消息。增量目标合并、未修改范围继承、旧约束保留与版本冲突检测。
- `agent/task_runtime.py`：`set_task` / `finish_task` 控制能力；默认不运行关键词路由。登记与独立只读操作可同轮调用；缺少任务、范围不符、禁止副作用、未决问题或缺少确认/日志时阻止写入。
- `tools/registry.py`：能力副作用与验证边界由工具声明；新增结构化结果适配，保留旧文本接口。
- `agent/verifier.py`：逐目标检查路径、目录、哈希、工具记录、原文证据、分类计划及执行回执；回执在收尾时检查实际内容，旧目录快照不能绕过新范围。
- 专用工具输出作为子任务结果；本地生成最终核验表和统计/计划展示，模型说明独立标记。同一分类计划的执行结果替换待执行展示。
- CLI 与 FastAPI 接入；`GET /api/conversations/{id}/tasks` 和 `.../tasks/{task_id}` 查看持久状态；UI 区分部分完成、待核实和等待输入。
- 下一次循环前也检查预算；模型协议所需的调用/结果配对继续保留，旧 V2 任务快照不重复送入后续上下文。

### 首批交付的明确边界

> 以下描述首批交付时状态。随后任务编辑、本地操作谓词和网页用户复核已补齐。真实模型与浏览器现场验收受当前环境网络限制，仍不能判定整个阶段验收完成。

1. 模型仍可能漏掉目标或登记不充分的条件；本地校验不能证明需求理解正确。未映射为副作用限制的文本约束标记待复核，尚无通用约束编译器。
2. `tool_success` 只证明工具调用，证据有效只证明引用可用；两者均不会自动标记语义完成。语义评估和用户复核闭环仍需扩展。
3. 当前增量修改支持追加/更新目标并保留旧约束；放宽约束、删除目标和结构化选项绑定待后续编辑协议实现。数字回复仍需模型依据上下文解释，不会本地隐式执行 latest 计划。
4. 仍复用原分类计划与去重执行器，尚无通用 Plan/Operation 恢复协议；任务检查点可查询不代表任务能自动恢复。CLI 的长期文件证据跨进程复用也依赖第三阶段文档库。
5. 暂未完成按任务裁剪全部旧工具明细、持久全文索引或向量检索；检索覆盖范围不因本次升级改变。
6. 首批离线验证不调用真实模型 API。多语言脚本用例验证控制路径不受关键词影响，不证明真实自然语言理解的泛化率。真实模型成功率、性能和费用需另做配对与保留集评测。

### 运行结束事实与只读诊断补充

形成方案与执行状态分开核验，`plan_ready` 不因后续执行而失效。运行结束原因作为本地事实持久化，并进入对话；失败、中止及部分完成直接给出依据。`inspect_run` 查询并结束本轮，不恢复旧任务；模型仍负责理解当前请求。V2 的近期工具历史也受字符预算约束，完整配对归档，原始 UI 记录保留。
